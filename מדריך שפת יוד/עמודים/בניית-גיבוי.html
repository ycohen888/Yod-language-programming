בניית תוכנת גיבוי משורת קוד עד EXE

מדריך מלא לבניית תוכנה אמיתית בשפת יוד — על בסיס הפרויקט פרוייקט דוגמה/גיבוי/. נעבור משלב הרעיון, דרך מודל נתונים, סנכרון, ממשק, FTP, תרגום ואריזה.

איך להשתמש במדריך: קראו לפי הסדר בפעם הראשונה. בכל פרק — בנו את השכבה בעצמכם, ואז השוו לקוד בפרויקט. מדריך המשתמש של האפליקציה נמצא בתוך הפרויקט ב־מדריך/מדריך.html (נפתח מתפריט עזרה) — כאן לומדים איך כותבים את התוכנה.

1. מה בונים ולמה

התוכנה מסנכרנת קבצים בין מקור (A) ל־יעד (B):

  • קבצים חדשים או שעודכנו — מועתקים לשני הכיוונים (ביעד מקומי).
  • מחיקה במקור — מוחקת גם ביעד; מחיקה ביעד לבדה לא נוגעת במקור (בסנכרון הבא הקובץ חוזר מ־A).
  • יעד יכול להיות תיקייה מקומית או שרת FTP / FTPS (אז הסנכרון חד־כיווני: מקור→שרת).
  • כמה «תוכניות גיבוי», הסתעפויות (forks), גיבוי אוטומטי, יומן וממשק HTML.

זו לא דוגמת «שלום עולם» — זו אפליקציית שולחן־עבודה מלאה: מצב קבוע בדיסק, עבודה ברקע בלי להקפיא UI, וחבילת EXE למשתמש קצה.

2. ארכיטקטורה ומפת קבצים

הפרויקט מחולק למודולים — כל קובץ .יוד אחראי על שכבה אחת:

3. שלד פרויקט ונקודת כניסה

צרו תיקייה (למשל גיבוי/) עם התחל.יוד. פתחו אותה בעורך יוד והריצו ב־F5, או מהקונסול:

בתחילת הפרויקט טוענים ספריות מובנות, ואז מודולי הפרויקט:

מלכודת שמות: אחרי כלול "..\עיצוב\…" השם רשת מתייחס למחלקת עיצוב. לכן שומרים מודול_רשת = רשת לפני טעינת העיצוב, ובקוד FTP משתמשים ב־מודול_רשת.FTP_….

דרישות להרצה: Windows + WebView2, ותיקיית האחות פרוייקט דוגמה/עיצוב/ (נכסי Bootstrap והמנוע).

4. מודל נתונים ואחסון

כל «תוכנית גיבוי» היא מילון עם מקור, יעד, הגדרות שרת, מרווח אוטומטי ועוד. ב־אחסון.יוד:

שמירה וטעינה ל־JSON בדיסק:

  • נתונים/תוכניות.json — רשימת התוכניות
  • נתונים/מצב/pN.json — מניפסט קבצים לכל תוכנית (לדילוג מהיר)
  • נתונים/העדפות.json — שפת ממשק וכו'
נרמול: נרמל_תוכנית ממלא שדות חסרים בגרסאות ישנות של הקובץ — כך שדרוג התוכנה לא שובר הגדרות קיימות.

5. סריקת קבצים והתעלמות

לפני השוואה בונים מפה: מפתח = נתיב יחסי מהשורש, ערך = מידע (גודל, זמן, האם תיקייה). שמות ברשימת «התעלם» מדלגים לגמרי (כולל תוכן בתיקייה).

בסריקה ארוכה משתמשים ב־התחל_מצב_סריקה / צעד_סריקה באצוות (גודל_אצוות_סריקה ב־הגדרות.יוד) — כדי שהממשק יישאר מגיב.

6. מנוע סנכרון בסיסי

לכל מפתח יחסי מחליטים מה לעשות ומוסיפים לפעולה לתור:

  • קיים רק ב־A → העתק ל־B (או צור תיקייה)
  • קיים רק ב־B ובמניפסט → מחיקה לפי מקור (או שחזור ל־A במקומי)
  • קיים בשניהם עם אותו גודל → דילוג
  • גודל שונה → העתק ממקור ליעד
למה לא לפי זמן שינוי? אחרי העתקה, הזמן ביעד שונה מהמקור — והסנכרון הבא היה מעתיק שוב ושוב. גודל זהה = אותו תוכן לצורך הגיבוי הזה.

7. אצוות, טיימרים וממשק שלא קופא

חלונות.הצג() רץ בלולאת הודעות. אם תעתיקו אלפי קבצים ברצף באותה קריאה — החלון «ימות». הפתרון בפרויקט:

  1. בניית תור הפעולות בשלבים (צעד_בניית_תור)
  2. ביצוע באצוות קטנות (בצע_אצווה — לרוב קובץ אחד בכל טיק)
  3. טיימרים.כל_כמה / טיימרים.אחרי בין השלבים

ב־הגדרות.יוד גם ספי מעבד/זיכרון: בעומס כבד הסנכרון ממתין (מרווח_המתנה_עומס_מס) במקום לחנוק את המחשב.

8. מניפסט — דילוג מהיר

אחרי סנכרון מוצלח נשמר מניפסט: רשימת מפתחות + גדלים. בפתיחת סנכרון הבא:

  1. בודקים במהירות דגימות מול הדיסק (אמת_רשומת_מניפסט)
  2. אם אין שינוי — מדלגים על סריקה והשוואה מלאה
  3. אם יש שינוי — סריקה מלאה ובניית תור

זה חוסך זמן כשרוב התוכניות לא השתנו, במיוחד עם גיבוי אוטומטי כל כמה דקות.

9. ממשק עם ספריית עיצוב

הממשק הוא HTML בתוך חלונות.דפדפן (WebView2), דרך ספריית עיצוב — לא וידג'טים Win32 לכל כפתור.

ב־בנה_ממשק_עיצוב בונים רכיבים כמו:

  • סרגל_עליון — דשבורד / הגדרות / תוכנית / יומן / עזרה
  • כרטיס — מקטעים בעמוד
  • תצוגת_עץ — משפחות תוכניות והסתעפויות
  • הצגת_קבצים — דפדוף מקור ויעד
  • כפתור, שדה, פס_התקדמות, טוסטים

בחירת תיקיות מקומיות נעשית ב־חלונות.בחר_תיקייה (חלון native) — כדי לקבל נתיב מלא אמין. אישורים קריטיים: חלונות.שאל / חלונות.הודעה.

10. דשבורד חי ויומן

בזמן סנכרון הממשק מציג:

  • מצב נוכחי (סריקה / השוואה / העתקה / העלאה)
  • פס התקדמות + מהירות (במיוחד ב־FTP)
  • יומן פעילות עם סינון (מידע / אזהרה / שגיאה)
  • אפשרות ביטול באמצע

הוסף_ליומן כותב לרשימה בזיכרון ומסמן שצריך לרענן את ה־UI (לא בכל שורה מיד — כדי לא להאט). כפתור «סנכרן» קורא ל־בקש_סנכרון / התחל_סנכרון — לא מתחיל אוטומטית רק מפתיחת התפריט.

11. הסתעפויות (פורקים)

תחת תיקיית אב (למשל pp1) אפשר לשמור כמה גרסאות יעד:

פורקים.יוד מחשב שמות (שם_תיקיית_יעד), מעביר תיקיות בהסתעפות חדשה (צור_פורק_מתוכנית), ובונה עץ למשפחות ב־UI (בנה_עץ_תוכניות). רק ברירת מחדל אחת לא־קפואה לכל משפחה — שמור_תוכניות מתקן אם נשמרו שתיים.

12. יעד מרוחק — FTP / FTPS

כש־סוג_יעד הוא FTP או FTPS:

  • חיבור ברקע: התחל_התחברות_מרוחק_ברקע + סקר מצב
  • סריקת מקור מקומית; יעד מרוחק מושווה מול מניפסט שרת (בלי LIST מלא — מונע הקפאה)
  • מניפסט ממקומי לא נספר כמצב השרת — אחרי מעבר ממקומי→FTP מועלה הכל מחדש
  • תור פעולות: העלה, מחק_מרוחק, צור_תיקיה_מרוחקת
  • חד־כיווני בלבד: מקור מקומי → שרת

בשדה הכתובת מזינים שם שרת בלבד (בלי ftp://). «בדוק חיבור» מאמת בלי לסנכרן. אם כבר סנכרנתם מקומית ואז לשרת וראיתם שרק חלק עלה — מחקו נתונים/מצב/<מזהה>.json או החליפו סוג יעד (מאפס מניפסט) וסנכרנו שוב. ראו גם ספריית רשת.

13. תרגום ממשק (i18n)

ספריית תרגום + קבצי תרגומים/en.po, תרגומים/fr.po. עטיפה קצרה בכל ה־UI:

שם התיקייה: הקטלוגים ב־תרגומים/ (לא תרגום/) — כדי שלא יתנגשו עם ספריית המערכת כלול "תרגום".

14. מדריך משתמש, נכסים ואריזה ל־EXE

מדריך.יוד מחפש מדריך/מדריך.html ליד תיקיית ההרצה ופותח אותו בתוך החלון. לוגו: נכסים/לוגו.png / לוגו.b64. איקון EXE: app.ico בתיקיית הפרויקט.

בעורך יוד: תפריט הרצה ← «ארוז ל־EXE», ואז «פתח מיקום EXE» לפתיחת dist_exe בסייר. פירוט נוסף: ארוז.

15. בדיקות בלי UI

קבצי בדיקה_*.יוד בפרויקט מאפשרים לבדוק סנכרון, מרוחק, פורקים ומניפסט בלי לפתוח את כל הממשק — לעיתים עם stubs לפונקציות UI. מומלץ: אחרי שינוי ב־סנכרון.יוד / סריקה.יוד — להריץ בדיקה רלוונטית על תיקיות זמניות קטנות.

סדר בנייה מומלץ (מתרגול)

  1. תיקייה + התחל.יוד + הדפסת «שלום»
  2. תוכנית_ריקה + שמירה/טעינה JSON
  3. סריקת תיקייה אחת למפה
  4. השוואה + העתקה סינכרונית על 2–3 קבצים
  5. פיצול לאצוות עם טיימר
  6. מניפסט ודילוג
  7. חלון + עיצוב + כפתור «סנכרן»
  8. יומן ופס התקדמות
  9. פורקים
  10. FTP
  11. תרגום + מדריך HTML + ארוז

זה בדיוק הסדר שבו נבנתה שכבות התוכנה — אל תקפצו ל־UI לפני שיש מנוע שעובד בקונסול.
